# 个股多维度研究

围绕公司的核心矛盾和市场预期形成有证据的研究判断。主 Agent 负责分析、计算和 CIO 整合；Sub-agent 承担边界清晰的数据采集、长文检索和指定证据提取。四种业务场景保留独立入口，共用以下执行规则。

## 研究原则

- 关键事实和数值可追溯到来源，注明日期、报告期、单位及必要口径。区分事实、推断、假设和未知，不把行业常识写成公司事实。
- 数值精度与证据精度一致；不能可靠量化时说明原因。结论应包含最有力的反方证据及可能改变判断的条件。
- 不提供面向具体用户的买卖点、止盈止损或仓位建议。量化策略仅作为可回测、可证伪的研究假设，未回测时标注“待验证”。
- 按重要性分配篇幅，不为填满模板罗列指标、补齐无关小节或强行配图。图表与尾注遵守当前系统的渲染及引用规范。

## 工具与能力核对

只读取本次任务需要的数据技能及参考文件：

| 需求 | 工具或技能 |
|---|---|
| 公司资料、财务、行情、估值指标、资金流、行业归属 | `hedgehog-company-index-data` |
| 新闻、研报、公告及原文 | `hedgehog-news-reports` |
| 基于 OHLCV 本地计算技术指标 | `tech-indicators` |
| 金融计算与估值 | `fin-calc`、`company-valuation` 或宿主提供的对应能力 |
| 常规派生数值 | 当前可用计算工具或运行时允许的脚本 |

取数或派发前，核对相关接口的字段、时间范围、条数上限和数据口径；以当前数据技能文档及工具校验为准，不在研究模板中另写一套接口参数。

- `getStockBasic` 用于核实公司身份；价格取行情接口，PE/PB、市值等取 `queryDailyBasic`。
- 区分单次窗口限制与历史可访问范围：前者可按文档分段，后者不能靠分段突破。分段结果核对实际覆盖范围、截断和重叠，不因请求成功就宣称区间完整。
- 需要 200 个交易日时按交易日历确定区间，兼顾指标预热期；不能以 200 个自然日代替。样本不足时披露实际条数。
- 复权方式须经来源确认。接口未声明支持的参数不能强传；无法确认时标注“复权方式未确认”，文件名、图表和结论不能标成前复权。受除权影响且无法验证的跨期收益和技术信号不作可靠判断。
- 确认不支持的参数或历史范围后，调整到可验证的范围、使用已确认可用的其他来源，或披露缺口；不重复尝试同一不支持的请求。

## 分工与上下文控制

### 数据子任务

将需要处理大量原始内容的采集或提取工作交给 Sub-agent，独立的数据任务可并行。主 Agent 先定义用途、所需字段或证据、时间范围、已知接口限制及返回内容，不固定子任务数量。

- 一个子任务完成一个明确的数据目标，例如“获取五年核心财务序列”或“从最新财报提取受限资产和债务期限的原文证据”；不按每个年份、字段或文件再拆任务。
- 不把复杂研究判断、估值方法选择、整篇分析成稿或 CIO 整合委派给 Sub-agent，也不为计算单独创建子任务；数据子任务自行完成采集与提取，不再嵌套派发。
- 共用的公告、估值历史和资金流只采集一次。先复用已有且口径合适的材料，只有影响判断的证据缺口才补取。
- 公告、新闻、研报等需要语义阅读的材料，由采集 Sub-agent 回读落盘文件，按任务目标总结或提取证据；返回关键事实、必要摘录、来源定位、日期与口径、缺口及真实文件路径。篇幅以支持主 Agent 判断为准，不统一限制为 800 tokens，也不带回完整宽表和长原文。
- 长序列供主 Agent 的程序直接从文件读取；返回必要字段、结构和文件位置即可，无需把整个序列复制进消息。派生数值留给主 Agent 批量计算。
- 有疑点时优先向原子任务定向追问，或由主 Agent 读取相关片段；不为核对一个数字重启完整流程。少量取数可由主 Agent 直接完成。

### 文件与返回约定

- 使用宿主指定的任务目录；Development 使用正式项目区域。遵循数据技能的落盘与来源登记方式，通过 `--out` 直接指定唯一且符合实际口径的文件名，原始材料只写新文件，派生内容单独保存。
- 支持直接落盘的数据接口在调用时指定输出路径，让响应直接保存为文件，工具回执只保留文件路径和必要元数据；不要先把完整响应输出到主 Agent 上下文，再由主 Agent 抄写到文件。仅直接返回少量基础信息的接口可正常读取；预计返回大量正文且不支持文件输出时，将查询与保存放在数据 Sub-agent 中完成。
- 需要总结或证据提取时，Sub-agent 将精简结果保存为 `sub-output-<short_title>.md`；纯结构化序列采集可只返回文件路径、字段说明、覆盖范围与缺口，无需另写叙述摘要。通过 `output_files` 返回实际产出路径，不在完成消息中附带整份原始数据。
- 不创建、读取、维护或交付 `sub-agent-list.txt`，也不依赖共享索引文件。子任务状态使用宿主调度能力，结果通过任务返回值与 `output_files` 获取；宿主内部自动生成的记录不属于研究流程输入或交付物。行数、字节数直接使用落盘回执，不重复检查或抄写。
- 主 Agent 默认只读精简结果和必要证据片段，避免全部原始数据进入上下文触发压缩。原始文件已落盘不代表可以全量回读：核查只读取相关字段、记录或段落，大范围阅读交给 Sub-agent 提取；计算工具直接从文件读入数据，完整结果保存到文件，仅返回分析所需的结果表或摘要。

## 计算

主 Agent 直接调用计算工具或允许的脚本完成派生数值，不以模型心算替代执行结果。同一数据集的单位换算、汇总、同比、占比和指标尽量一次批量完成；存在依赖时分批，不为每个表达式单独组织一轮模型调用。

已有同口径指标可直接复用。工具不支持批量时可使用允许的脚本；不能假定 `math_calc` 支持未提供的参数，也不为规避运行时限制更换执行方式。保存必要的输入来源、公式或参数及结果，支持核对关键计算，无需逐项输出流水账。

财务计算核对币种、单位、合并口径及重述版本；累计利润和现金流不能直接当作单季度，资产负债表和比率不能通过简单差额还原单季度。分母为零、接近零或缺失时说明适用性，不填造结果。

## 工作流 A：基本面分析

**触发**：`基本面分析 [股票代码]` / `研究 [股票名称] 基本面`
**目标**：判断商业模式、竞争优势、财务质量、风险及估值。
**参考**：[基本面分析规范](references/fundamentals-agent.md)
**输出**：`final-output-analysis-fundamentals-{stock_code}.md`

1. 主 Agent 确认公司、研究截止日和核心问题，核对相关接口能力。
2. 复用已有材料，将核心财务序列、最新报告及指定附注等明确采集任务交给 Sub-agent；需要时并行，不固定数量。
3. 主 Agent 直接批量计算、解释异常和选择估值方法，按参考规范完成报告。只对会影响判断的缺口定向补查。
4. 长报告分段保存，按统一终检要求交付。

## 工作流 B：情绪分析

**触发**：`情绪分析 [股票代码]` / `[股票名称] 消息面分析`
**目标**：提炼市场叙事、多空分歧、资金表现及潜在催化剂。
**参考**：[情绪分析规范](references/sentiment-agent.md)
**输出**：`final-output-analysis-sentiment-{stock_code}.md`

1. 主 Agent 确认公司、研究截止日及所需信息窗口，核对新闻、公告、研报和市场数据的可访问范围。
2. 将公司重要资讯、相关行业事件等明确检索任务交给 Sub-agent；公告、估值和资金流优先复用，不要求每类凑满固定数量。
3. 主 Agent 完成必要的批量计算，评估证据与市场叙事，区分事实、观点和推断，形成专项报告。
4. 长报告分段保存，按统一终检要求交付。

## 工作流 C：技术分析

**触发**：`技术分析 [股票代码]` / `[股票名称] 技术面`
**目标**：刻画量价状态、关键区间及风险，有研究价值时提出待验证的量化假设。
**参考**：[技术分析规范](references/technicals-agent.md)
**输出**：`final-output-analysis-technicals-{stock_code}.md`

1. 主 Agent 确认观察窗口、交易日范围和可验证的价格口径。
2. 将行情采集交给数据 Sub-agent，返回实际覆盖范围、口径和文件路径；已有合适行情时直接复用。
3. 主 Agent 让计算工具读取行情文件，批量计算所需技术指标，分析量价状态和局限，不把本地计算委派给子任务。
4. 按参考规范成稿；长报告分段保存，按统一终检要求交付。

## 工作流 D：CIO 综合研报

**触发**：`整合报告 [股票代码]` / `生成研报 [股票名称]` / `深度分析 [股票代码]` / `分析 [股票名称]` / `全面分析 [股票名称]`
**目标**：形成跨基本面、情绪面和技术面的综合研究判断。
**参考**：[CIO 整合规范](references/cio-integration.md)
**输出**：`final-output-research-{stock_code}-{YYYYMMDD}.md`

根据用户请求选择以下路径：

- **整合已有报告**：从用户提供或当前任务已有的路径确认输入及覆盖范围，主 Agent 按 CIO 规范整合。用户只要求整合现有材料时，不擅自扩展为完整采集；缺失维度明确说明，不把部分材料称为完整覆盖。
- **从头完成完整研究**：统一规划三个维度的证据需求，共用数据只取一次，独立采集可并行。主 Agent 随证据就绪完成各维度分析，保存 A / B / C 对应的三份专项报告，再分段完成综合研报。无需顺序重跑三个工作流的准备和采集，也不另设分析型 Sub-agent。

两条路径均由主 Agent 核对跨维度矛盾、形成综合判断，按下方分段写入规则保存并终检。这里的三个研究维度不要求建立三位分析师 Agent。

## CIO 分段写入

为避免超过 LLM 单次输出上限，最终研报按章节分段写入，每完成一章就保存；章节过长时再按小节写入。首次创建文件，后续使用当前 Agent 支持的追加或编辑能力，修改已有内容时局部编辑，避免每次重新输出整篇。

读取顺序按证据需要安排，不限制一次只能读一份报告；发现矛盾可回读相关报告或数据片段。允许去重、重组和改写，保留关键证据、条件及引用，不要求原样搬入全文。摘要可先写或后补，最终置于正文之前；综合判断不受几十字暂存结论限制。

## 交付结构与终检

最终研报标题为 `# 【深度研报】{公司名称}（{股票代码}）- {YYYYMMDD}`，保留以下主结构，内部小节按重要性安排：

1. **研报摘要**：综合判断、核心矛盾、估值依据与适用条件、关键风险和跟踪变量。不能可靠估值时说明原因。
2. **基本面剖析**：商业模式、竞争优势、财务质量、风险与估值。
3. **情绪与消息面**：市场叙事、分歧证据、资金表现与催化剂。
4. **技术面量化**：可验证的量价状态、关键区间及局限；有研究价值时给出待验证的量化假设。
5. **尾注**：参考资料、实际使用的图表数据及 AI 生成提示，标题、顺序和格式服从当前系统规范，不重复添加。AI 提示说明内容由 AI 生成、仅供研究参考、不构成投资建议。

缺失维度应明确标注覆盖限制，不用空表或无依据内容补齐。各场景交付前检查：

- 关键判断有可追溯证据，来源日期不超过研究截止日，事实、假设和未知已区分。
- 报告期、单位、价格及估值基准一致；复权口径、数据缺口和未验证假设披露准确，核心计算可复现。
- 重要矛盾已经解释或明确保留，反方证据未因整合删去。
- 文件存在且内容完整，分段写入无章节重复、遗漏或截断；引用与图表指向真实材料，不以填满模板作为验收条件。

主 Agent 使用顶层 `selected_files` 列出实际生成的报告和交付必需的伴随文件；如已生成 HTML 版本，连同 Markdown 一并列出，保留真实路径。group/sub-agent 只返回 `output_files`，不调用最终交付工具。文件元数据由宿主管理，不另建索引文件作为交付前置条件。

最终文本回复提供研究摘要、重要局限和文件入口，不重复发送报告全文。
